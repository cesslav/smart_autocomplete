# Smart Autocomplete (Local LLM)

Умный автокомплит для VSCode: локальная LLM ранжирует кандидаты, отобранные
по статистике вашего кода и вашего стиля написания.

- **Статистика использования** — плагин учит, какие имена (классы, функции,
  переменные, методы) вы реально используете: принятые подсказки и вставленные
  имена повышают их приоритет.
- **Библиотека плагина** — словарь всех известных имён хранится локально в
  `dictionary.json` и постоянно пополняется сканированием воркспейса.
- **Локальная LLM** — кандидаты и последние строки кода отправляются маленькой
  модели на вашем компьютере (Ollama или любой OpenAI-совместимый сервер).
  Код никуда не уходит.
- **Гибридное UI** — лучший кандидат показывается ghost-text'ом (Tab —
  принять, Alt+]/Alt+[ — переключить), остальные — в привычном выпадающем
  списке подсказок VSCode.
- **Честный fallback** — если LLM недоступна или медленнее таймаута, список
  показывается по частоте использования, без ожидания.

## Как это работает

```
ввод символа
   │
   ├─ каждый новый символ отменяет предыдущий незавершённый запрос к LLM
   │
   ▼  (пауза debounceMs, по умолчанию 300 мс)
отсев по префиксу в dictionary.json (без учёта регистра)
   │   + топ maxCandidates по score = uses × 10 + seen
   ▼
промпт: последние contextLines строк кода + префикс + список кандидатов
   ▼
локальная LLM (Ollama /api/generate или /v1/chat/completions, temperature 0)
   ▼
{"completions": ["name1", "name2", ...]}
   ▼
UI:  ghost-text  ← лучший вариант (Tab — принять)
     dropdown    ← остальные варианты (как обычные подсказки VSCode)
```

Особенности:

- При вводе `.` (например, `obj.`) показываются только методы, свойства и
  функции из словаря.
- Ghost-text и выпадающий список разделяют **один** запрос к LLM (консолидация
  вызовов), так что модель вызывается один раз на паузу в наборе.
- При недоступности LLM (`timeout`, `fetch failed`, не-JSON ответ) показывается
  частотный ранжированный список — плагин никогда не «молчит».

### Режимы показа

| Режим | Ghost-text | Выпадающий список |
|---|---|---|
| `inline` (по умолчанию) | лучший кандидат | остальные кандидаты, автопоказ как у обычных подсказок (или по Ctrl+Space, если `suppressBuiltInSuggest` включён) |
| `widget` | нет | весь ранжированный список |

У наших пунктов в списке пометка в detail: `LLM · uses N · seen M` (или
`freq`, если LLM не участвовала).

## Установка

Требования: **Node.js 18+**, **VSCode 1.82+** (проверка: Help → About).

### Сборка в .vsix и установка в обычный VSCode

```bash
cd smart_autocomplete
npm install
npm run package                    # компиляция + smart-autocomplete-<версия>.vsix
code --install-extension smart-autocomplete-0.1.2.vsix
```

Или через UI: Extensions (Ctrl+Shift+X) → «… → Install from VSIX…».
После установки — Reload Window. Обновление: правки кода → `npm run package`
→ `code --install-extension …` → Reload.

Замечания по сборке: в `package.json` зафиксированы `@vscode/vsce 2.24.0` и
`undici 6.21.0` (overrides) — они работают на Node 18; vsce 3.x потребует
Node 20+.

### Режим разработки (F5)

Откройте папку `smart_autocomplete` в VSCode и нажмите F5 (конфигурация
«Run Extension»). Откроется новое окно **Extension Development Host** —
подсказки и все проверки работают в нём.

## Настройка локальной LLM

**Вариант 1 — [Ollama](https://ollama.com) (по умолчанию):**

```bash
# установка ollama, затем:
ollama pull qwen2.5-coder:1.5b      # хороший выбор для кода (есть 3b / 7b)
# альтернативы: gemma2:2b, phi3.5:3.8b, llama3.2:1b
```

**Вариант 2 — любой локальный OpenAI-совместимый сервер** (llama.cpp
`server`, vLLM, LM Studio, …):

- `smartAutocomplete.backend` → `openai`
- `smartAutocomplete.llmUrl` → например `http://localhost:8080`

Проверка, что сервер жив: `curl http://localhost:11434/api/tags`.

## Настройки

| Настройка | По умолчанию | Описание |
|---|---|---|
| `smartAutocomplete.enabled` | `true` | Включить/выключить плагин |
| `smartAutocomplete.mode` | `inline` | `inline` — ghost + список остальных (гибрид); `widget` — только выпадающий список |
| `smartAutocomplete.suppressBuiltInSuggest` | `false` | Выключить автопоказ списка (`editor.quickSuggestions=false`, глобально): остаётся только ghost-text, список — по Ctrl+Space. Предыдущее значение восстанавливается автоматически |
| `smartAutocomplete.debounceMs` | `300` | Пауза после последней клавиши перед запросом к LLM |
| `smartAutocomplete.llmTimeoutMs` | `2500` | Таймаут LLM; по истечении — частотный fallback. На CPU или при холодном старте модели увеличьте до 4000–6000 |
| `smartAutocomplete.backend` | `ollama` | `ollama` или `openai` (OpenAI-совместимый API) |
| `smartAutocomplete.llmUrl` | `http://localhost:11434` | URL локального LLM-сервера |
| `smartAutocomplete.llmModel` | `qwen2.5-coder:1.5b` | Имя модели на сервере |
| `smartAutocomplete.maxCandidates` | `30` | Сколько отфильтрованных кандидатов отправить в LLM |
| `smartAutocomplete.topN` | `5` | Сколько имён запросить у LLM |
| `smartAutocomplete.contextLines` | `8` | Сколько последних строк кода отдать в контекст |

## Команды

| Команда | Действие |
|---|---|
| `Smart Autocomplete: Rescan workspace` | Повторное сканирование воркспейса (до 4000 файлов, до 1 МБ на файл) |
| `Smart Autocomplete: Show identifier statistics` | Топ-200 имён: uses / seen / время последнего использования |
| `Smart Autocomplete: Reset usage statistics` | Обнулить счётчики использования (встречаемость в коде сохраняется) |

## Словарь и автоматическое индексирование

Словарь пополняется без участия пользователя:

- фоновый скан воркспейса через 3 с после активации (regex-извлечение классов,
  интерфейсов, функций, переменных и вызовов методов);
- индексация каждого открытого документа (трототированная очередь, 1 с);
- повторная индексация файла при каждом сохранении;
- учёт использования: любое вставленное целиком имя (принятая подсказка из
  списка или ghost-text, вставка, сниппет) увеличивает `uses`.

Приоритет имени: `score = uses × 10 + seen` — ваш личный опыт весит в 10 раз
сильнее, чем «случайно встречалось в коде». Лимит словаря — 200 000 записей.

## Структура проекта

| Файл | Назначение |
|---|---|
| `src/extension.ts` | Активация (с самодиагностикой), команды, статус-бар, подавление/восстановление автопоказа, авто-индексирование |
| `src/engine.ts` | Общий конвейер: префикс → отсев → debounce → LLM → ранжирование; отмена устаревших запросов, консолидация одновременных вызовов, fallback |
| `src/inlineProvider.ts` | Ghost-text: лучший кандидат (режим inline) |
| `src/completionProvider.ts` | Выпадающий список: остальные кандидаты (inline) / весь список (widget) |
| `src/dictionary.ts` | Словарь + статистика, JSON-персистентность, отсев по префиксу |
| `src/seed.ts` | Встроенный начальный словарь (~440 имён) |
| `src/scanner.ts` | Regex-извлечение имён из исходников |
| `src/context.ts` | Срез последних строк кода до курсора |
| `src/llm.ts` | Промпт, запрос к Ollama / OpenAI-совместимому API, разбор JSON-ответа |
| `src/stats.ts` | Статистика использования (целословные вставки) |
| `src/log.ts` | Output-канал «Smart Autocomplete» |
| `src/languages.ts` | Список языков и trigger-символов |

## Ограничения

- Извлечение имён — regex-сканирование (не парсинг AST): покрывает объявления
  и вызовы, но не все экзотические формы синтаксиса.
- VSCode не сообщает провайдерам факт принятия подсказки; учёт использования —
  эвристика по изменениям текста (высокая точность, редкие ложные
  срабатывания).
- Качество ранжирования зависит от модели: 1.5–4B на GPU дают хороший ответ за
  ~0.3–1 с; на CPU используйте модель ≤3B и увеличьте `llmTimeoutMs`
  (частотный fallback всё равно работает).
